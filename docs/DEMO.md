# Demo walkthrough — 8 to 10 minutes

Start with `python manage.py init --demo` followed by `python app.py`. Open http://127.0.0.1:8000. All fixture accounts use **Explore@12345**. The data is fictional. A fresh database has 40 sample bookings; existing local verification adds more.

## 1. Discovery — 1 minute
Open Discover. Show 12 destinations, categories and verified ratings. Search **Jaipur**, then clear the search and choose **Nature** with a budget of **3500**. Explain that the destination ordering uses actual review averages and the filters use stored tour prices. The visuals are local CSS illustrations, so the application needs no image service.

## 2. Tourist workflow — 2 minutes
Sign in as **tourist@stms.local**. Open My trips to show existing pending/confirmed/completed demo reservations and private itinerary items. Return to Discover, select a future departure and request **2 guests**. Open My trips to show the reservation and server-calculated total. Explain that it begins pending and collects no payment. The guest count reduces live availability; cancellation before departure releases seats.

## 3. Generative AI — 2 minutes
Open **AI planner ✦**. Choose Pink City Heritage, a future start date, **3 days**, **₹10,000**, **2 travellers**, and interests **heritage, local culture, slow mornings and relaxed walks**. Generate the plan.

With NVIDIA_API_KEY configured, the server sends the selected catalog description/preferences to NVIDIA NIM and validates structured output. Highlight morning/afternoon/evening activities, dates and the packing list. Click **Save to my itinerary**, then open My trips to show the three new entries. Explain that saving a plan does not reserve a tour.

Without a key, demonstrate **Try the catalog preview** and explicitly say the fixed preview is not generated by a model. The actual NVIDIA integration is implemented but requires the owner's key to exercise live inference.

## 4. Guide operations — 1 minute
Sign out; sign in as **guide@stms.local**. Open Operations. Show only reservations assigned to Priya Sharma. Confirm a pending booking for one of her tours. Completion is allowed only on/after departure; historical confirmed reservations can be completed if available. Guides cannot edit destinations or access another guide's reservations.

## 5. Administrator — 2 minutes
Sign out; sign in as **admin@stms.local**. Open Operations to show user/destination/booking counts, reserved value and status breakdowns. Select a destination in the editor to demonstrate persistent catalog fields, then use the departure form to schedule a future tour with a guide, price and capacity. Open the recent audit trail.

Open Support to show the mixture of open/resolved requests. Enter a response on an open request and resolve it. Sign back in as that request's tourist if demonstrating the private response.

## 6. Architecture and deployment — 1 minute
Show `docs/SRS.md`, `fixtures/demo.json`, `app.py`, `ai_planner.py`, `database.py`, and `vercel.json`. Explain browser → Python JSON API → SQLite locally/PostgreSQL on Vercel. The NVIDIA key stays on the server. The Vercel function uses persistent hosted PostgreSQL; the static build contains only three browser assets. Run the tests and show the GitHub Actions workflow.

Suggested closing demo action: leave the tourist signed in with an itinerary visible, so the audience can inspect a complete trip plan.
